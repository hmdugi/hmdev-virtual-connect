# 개인정보 보호 구현과 검증

기준: 2026-11-11. 익명 활동 보장과 개인정보 보호를 구분합니다. 다른 이용자의 비공개 정보를 서버 응답에서 제외하는 것이 기준이며, 개발자도구 차단·난독화로 보호한다고 주장하지 않습니다.

## 공개와 비공개

| 정보 | 처리 |
|---|---|
| 승인된 활동명·소개·공식 주소·공개 크레딧 | 탐색 API로 전달. 누구나 개발자도구에서 확인 가능 |
| 이메일·로그인 제공자 정보 | 인증 제공자가 처리. 서비스 API 응답에는 미포함 |
| 내부 인증 계정 ID·신청자 계정 연결·운영자 ID | 서버 내부 권한 검사에만 사용. 본인/운영자 UI에도 불필요한 ID를 보내지 않음 |
| 접수번호·공개 프로필 ID | 식별에 필요한 무작위 ID. ID를 알아도 비공개 신청 접근 권한이 생기지 않음 |
| 신청 내용·확인 문구 | 본인 신청 상태에 필요한 항목만 전달. 운영자는 검토에 필요한 신청·근거를 열람 |
| 운영자 내부 메모·내부 감사 이력 | 일반 사용자에게 전달하지 않음. 신청자 안내와 별도 저장 |
| 토큰·서비스 비밀키 | 토큰은 HttpOnly 쿠키, 서비스 키는 서버 환경변수. localStorage/응답 본문에 넣지 않음 |

브라우저 소유자는 본인의 입력·네트워크 요청·쿠키를 개발자도구로 확인할 수 있습니다. HttpOnly는 페이지 JavaScript의 쿠키 읽기를 막는 속성이며 개발자도구에서 본인 쿠키를 숨기는 기능이 아닙니다. 운영자는 승인 검토에 필요한 비공개 자료를 볼 수 있으며, 서버/DB 관리자로부터 모든 데이터를 숨기는 종단간 암호화 서비스는 아닙니다.

## 이번 수정

- DB 레코드를 그대로 반환하지 않고, 공개/본인/검토자별 허용 필드를 명시합니다. 중첩 작업 참여자도 ID·역할만 반환합니다.
- /api/me의 내부 인증 ID 제거. 신청 응답의 ownerId 제거. 사용하지 않는 감사 로그 응답 제거.
- 신청자 안내(reviewMessage)와 내부 메모(reviewNote) 분리. 기존 내부 메모는 안내로 자동 전환하지 않습니다.
- 모든 API 응답 no-store/no-cache, Vary: Cookie, no-referrer. 정적 참여 페이지도 Vercel 캐시 금지 설정.
- 로그아웃·페이지 이탈 시 신청/검토 DOM, 입력 폼, 메모리 자료를 정리합니다. 뒤로가기로 복원된 페이지는 인증을 다시 확인하도록 새로고침합니다. 오래된 비동기 조회가 정리 후 화면을 다시 채우지 않도록 조회 버전을 검사합니다.
- 인증 제공자의 로그아웃 실패에도 브라우저 쿠키를 제거하고, 서버 종료 여부는 별도 안내합니다.
- 앱 코드에서 이메일·인증 코드·요청 본문·토큰을 console/log로 출력하지 않습니다. 오류 응답은 내부 예외·공급자 응답을 그대로 반환하지 않습니다.

## 검증

개인정보 회귀 테스트 4개 추가. 계정 A의 신청이 B에게 안 보이는지, B가 운영자 경로를 호출해도 거절되는지, 내부 메모·계정 ID·추가된 비공개 필드가 응답에 포함되지 않는지, 민감한 오류가 반사되지 않는지, 캐시 헤더와 로그아웃 쿠키 제거를 확인합니다. 기존 테스트 포함 버튜버 저장소 14개 통과.

## 공개 전 남음

실제 Supabase Auth·Postgres/RLS·Vercel 배포 환경에서 권한과 캐시 헤더를 검증해야 합니다. 호스팅/인증 제공자의 접속 로그·IP·오류 수집 설정과 보관 기간도 별도로 확인해야 합니다. 실제 브라우저의 로그아웃/뒤로가기/동시 요청 정리까지는 이번에 검증하지 않았습니다. 코드 테스트 통과만으로 개인정보 유출 가능성이 0이라고 주장하지 않습니다.

공개 전 운영자 연락처, 신청 정보 보관·삭제 절차를 확정합니다. 불필요한 실명·전화번호·신분증·주소를 수집하지 않습니다. 공개 소개에 민감한 개인정보가 포함되었는지는 승인 단계에서 확인합니다.
