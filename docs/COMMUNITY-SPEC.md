# 버츄링크 커뮤니티·협업 기능 명세

기준: 2026-11-11. 사용자 요청으로 확장한 구현 기준입니다. 아래 기능은 명세이며 구현 완료를 뜻하지 않습니다. 기존 탐색/추천/프로필 신청 MVP와 구분합니다. 실기기 검증은 현재 작업 범위에서 제외합니다.

## 계정·이용 원칙

- 각 프로젝트는 독립 계정과 프로필·세션·권한을 사용합니다. hmdev 통합 로그인을 만들지 않습니다.
- 공용 DB를 쓰더라도 같은 인증 사용자 ID를 모든 서비스의 회원 자격으로 취급하지 않습니다. 프로젝트별 가입·동의·접근 권한을 분리하고 검증합니다. 독립 Supabase Auth 프로젝트 사용 여부는 자원·비용과 함께 결정하며 분리 완료로 표시하지 않습니다.
- 비로그인은 공개 글/댓글/프로필/모집 글 읽기와 검색·필터만 가능합니다.
- 작성·댓글·추천·저장·지원·제안·신고·차단 등 참여는 로그인 필수입니다. 서버에서 매 요청 검증합니다.
- 계정 하나에 시청자·방송인·일러스트·리깅·디자인 역할을 복수 설정할 수 있습니다. 역할 선택과 활동/소속 확인 배지는 별개입니다.
- 합방 제안 작성·지원은 방송인 프로필을 연결한 회원에게 허용합니다. 프로필 연결은 본인 신청·검토 흐름을 사용하며, 타인의 채널 URL 입력만으로 방송인 권한을 주지 않습니다.
- 기업 공식 모집 작성 권한은 소속 확인 후 부여합니다. 일반 회원의 오디션 정보 공유는 허용하되 공식 공고와 구분합니다.
- 이메일, 로그인 계정 ID, 비공개 연락처, 지원서, 운영자 메모는 공개 API에 포함하지 않습니다. 공개 닉네임·프로필과 계정 정보를 분리합니다.
- 읽기 제한은 공개 자료에만 적용합니다. 비공개 지원서/제안/신고/알림/개인 설정은 본인 또는 업무상 필요한 당사자만 조회합니다.

## 게시판 구조

대분류와 하위 게시판은 별도 주소·제목·설명을 갖되 공통 글/댓글 시스템을 공유합니다. 초기 글이 적으면 대분류의 통합 목록으로도 볼 수 있습니다. 이용자가 다른 게시판으로 글을 옮겨 다니지 않도록 말머리·태그·검색을 제공합니다.

| 대분류 | 하위 공간 | 주요 말머리·입력 |
|---|---|---|
| 방송 이야기 | YouTube / 치지직 / SOOP / 기타·여러 플랫폼 | 질문·정보·방송 후기·운영 노하우, 대상 플랫폼 |
| 캐릭터 제작 방식 | Live2D / 3D / PNG·기타 | 제작·트래킹·표정·도구·문제 해결 |
| 그림·작품 | 일러스트 / 팬아트 | 원작/팬아트, 원작자·대상 방송인 크레딧, AI 사용 여부 |
| 리깅 | 리깅 이야기·작업 공유 | Live2D/3D, 질문·시연·작업 후기 |
| 작가 소개 | 일러스트 / 리깅 / 디자인 / 복합 | 공개 포트폴리오, 제공 분야, 의뢰 가능 여부, 자기소개 |
| 디자이너 찾기 | 일러스트 / 리깅 / 방송 디자인 / 기타 | 예산·작업 범위·납기·권리·지원 기한·모집 상태·작업 상태 |
| 단기·이벤트 디자인 | 하루 행사·방송 소품·썸네일·임시 오버레이 등 | 사용일·사용 기간·상업 방송 사용 범위·전달 형식·예산·긴급 여부 |
| 기업세 오디션 | 공식 모집 / 공고 공유 | 회사·공식 원문·접수 기한·활동 분야·지원 자격·비용 여부·확인 상태 |
| 합방 제의 | 게임 / 토크 / 음악 / 행사 / 기타 | 플랫폼·일시·소요 시간·인원·콘텐츠·진행 방식·방송 송출/클립 조건 |
| 공통 | 자유 이야기 / 이용 질문 / 공지 | 공지·문의·제안 |

'단기·이벤트 디자인'은 목적과 사용 기간을 구분한 작업입니다. 무조건 저가·저품질로 취급하지 않습니다. 신의상·장기 모델 제작과 혼동되지 않도록 사용 범위와 원본 전달을 명시합니다.

## 공통 글·댓글

- 목록: 게시판·말머리·제목·작성자 공개 닉네임·작성 시각·댓글 수·추천 수. 날짜/검색/분야/모집 상태 필터, 최신순 기본.
- 글: 제목·본문·공개 첨부/외부 작품 링크·말머리·관련 프로필. 본문 HTML은 그대로 실행하지 않고 정제된 형식만 허용합니다.
- 댓글/답글: 로그인 작성·수정·삭제, 원문 작성자 표시, 신고·차단. 삭제된 부모 댓글은 자리만 남겨 답글 맥락을 유지합니다.
- 추천: 회원 1명당 글 1개, 취소 가능, 중복/동시 요청 멱등 처리. 추천한 회원 명단은 공개하지 않습니다.
- 저장: 회원 전용. 서버 본인 목록이며 타인에게 공개하지 않습니다. 기존 비로그인 로컬 즐겨찾기는 변경 대상입니다.
- 내 활동: 작성 글·댓글·저장·내 모집·내 지원·알림·차단 목록.
- 차단: 차단한 상대의 글/댓글을 내 화면에서 가리고 상호 신규 지원·제안을 제한합니다. 차단 대상이 일반 공개 글을 완전히 읽지 못하게 하는 보안 수단으로 설명하지 않습니다.
- 신고: 사칭·도배·괴롭힘·무단 사용·개인정보 노출·허위 모집 등. 신고 내용/신고자 비공개, 담당 운영자 접근 및 처리 이력.
- 첨부: 이미지 파일 형식/크기/개수 제한, EXIF 등 불필요한 메타데이터 제거, SVG/실행 파일 금지, 저장 공간/업로드 빈도 제한. 초안·비공개 첨부는 공개 버킷 URL로 제공하지 않습니다.
- 작품: 작성자가 권리·공개 허용을 확인하고 원작/참고/AI 사용 여부를 표시합니다. 팬아트는 대상 인물을 연결하되 공식 승인으로 오인시키지 않습니다.
- 알림: 댓글·답글·내 모집 지원·지원 결과·상태 변경을 서비스 내부 알림으로 제공. 이메일 발송은 별도 동의/설정 후 확장합니다.
- 접근성: 키보드·명시적 입력 레이블·오류 위치·상태 텍스트. 상태를 색상만으로 표시하지 않습니다.
- 페이지네이션·검색 결과 제한·중복 제출 방지·일별/분당 작성 제한·새 계정 링크/업로드 제한을 서버에 적용합니다. 신고 누적만으로 자동 영구 제재하지 않습니다.

## 디자이너 찾기·단기 작업 상태

모집과 작업 상태는 독립적으로 저장합니다. 제목에 사람이 직접 적는 문구가 아니라 서버 상태로부터 배지를 생성합니다.

- 모집: 모집중 → 모집마감 / 모집취소. 매칭 수락 시 모집마감 여부를 선택하며 여러 명 모집도 지원합니다.
- 매칭: 미매칭 / 일부매칭 / 매칭완료. 목표 인원과 수락된 지원으로 계산합니다.
- 작업: 시작전 / 진행중 / 완료확인대기 / 작업완료 / 작업취소. 합의된 당사자와 상태별 권한을 검사합니다.
- 목록 예: [매칭완료] [진행중] 행사 하루용 방송 오버레이 제작자를 찾습니다.
- 작업완료는 모집자 완료 요청 후 연결된 작업자의 확인으로 표시합니다. 일방 완료 표시는 '완료확인대기'. 다수 작업자는 개별 상태를 기록하고 전체 완료 조건을 계산합니다.
- 수락 후 작업 범위/보수/납기 변경은 변경 이력을 남기며 연결된 상대에게 알립니다. 플랫폼 내 정산·에스크로·거래 보증은 제공하지 않습니다.
- 지원 전 핵심 조건(금액/무보수 명시, 납기, 권리, 전달물)이 없으면 게시할 수 없습니다. 금액 비공개 협의는 그 사실을 명시합니다.

## 지원·제안 흐름

1. 로그인 회원이 모집 조건을 보고 지원합니다. 공개 댓글과 비공개 지원서를 구분합니다.
2. 지원서: 자기소개·관련 공개 프로필/작업·희망 조건. 이메일·전화번호·주소 제출을 필수로 요구하지 않습니다.
3. 지원 상태: 대기 / 수락 / 거절 / 지원취소. 같은 모집의 중복 활성 지원 금지, 본인 글 지원 금지, 정원 초과 동시 수락 방지.
4. 작성자와 해당 지원자만 지원서를 봅니다. 목록 공개 응답에 지원자 ID/연락처/지원 내용이 섞이지 않습니다.
5. 수락 후 당사자만 보는 작업 카드와 비공개 전달 메모를 제공합니다. 실시간 채팅은 1차 범위 밖이며, 지원서/후속 메모로 연락 흐름을 완성합니다.
6. 연락처 공유는 수락 후 본인 선택으로만 제공합니다. 공개 프로필과 별도로 동의를 받으며 철회/삭제 처리를 정의합니다.
7. 탈퇴·글 삭제 시 거래 이력과 개인정보 처리 범위를 정하고 안내합니다. 보관 기간을 임의 확정하거나 무기한 보관하지 않습니다.

## 합방 전용

- 방송인 프로필 소유가 확인된 회원만 모집·지원. 일반 회원은 공개 모집 글만 읽습니다.
- 필수: 콘텐츠·일정/시간대·예상 시간·플랫폼·인원·필요 준비·방송 동시 송출·클립/다시보기 사용 조건.
- 방송 규모 조건이 필요하면 작성자가 명시하되 플랫폼이 인기도를 추정하거나 수치를 만들어 주지 않습니다.
- 지원자 닉네임·채널을 공개 모집 글에 자동 나열하지 않습니다. 수락 후 참가자 공개는 각자 동의가 필요합니다.
- 일정 확정/변경/취소·정원·중복 지원·차단/제재 계정 참여를 처리합니다. 공개 글에 개인 연락처를 노출하지 않습니다.

## 오디션 전용

- 제목의 [공식모집]은 소속 확인된 계정만 사용합니다. [공고공유]는 공식 원문 링크를 필수로 합니다.
- 접수 마감일/시간대·공식 접수처를 표시하고 기한이 지나면 [접수마감] 배지를 계산합니다. 알 수 없는 기한은 미확인 표시.
- 공식·공유·확인중·정정·마감 상태를 구분하고 원문 수정/삭제 신고를 받습니다. 운영자 확인을 합격/계약 안전 보증으로 표시하지 않습니다.
- 이력서·주민등록증·실명·주소·오디션 영상을 플랫폼에서 대신 수집하지 않습니다. 최초 버전은 공식 지원처로 연결합니다.
- 가입비/선납금/불명확한 비용이 있으면 명시하고 사칭·허위 모집 신고를 제공합니다.
- 실제 인물의 채용/오디션 합격 자동 평가·선발은 구현하지 않습니다.

## 데이터·권한 설계

기존 vc_state 단일 JSON은 초기 프로필 신청용입니다. 커뮤니티 글·댓글·추천·지원 내역을 계속 붙이지 않습니다. 정규 테이블·인덱스·페이지네이션·트랜잭션을 사용합니다.

- members/public_profiles/role_verifications: 서비스 회원·공개 프로필·운영자 역할 검증 분리.
- boards/posts/post_revisions/comments/post_votes/bookmarks: 공통 게시판/글/댓글/추천/저장.
- opportunities/applications/engagements/engagement_events: 모집·비공개 지원·연결된 작업·상태 이력.
- reports/blocks/notifications/moderation_events: 비공개 신고·차단·알림·감사 기록.
- attachments: 업로드 주체·연결된 글·공개 상태·파일 검사 결과.
- posts 공개 읽기 조건과 applications 당사자 읽기를 각각 정의합니다. 이메일·Auth UID 대신 공개 프로필 식별자를 반환합니다.
- DB 직접 접근은 기본 거부, 서버에서 세션 검증·서비스 회원 검증·객체 소유/당사자/운영자 검증. 사용자 입력 role/admin/ownerId를 신뢰하지 않습니다.
- 상태 전이는 트랜잭션과 현재 상태 조건을 사용합니다. 사용자마다 추가 페이지 요청을 해도 타인 지원서가 유출되지 않아야 합니다.
- 로그에 토큰·이메일·본문·지원서·연락처를 남기지 않습니다. 로그아웃과 세션 만료 시 비공개 UI/메모리를 정리합니다.
- 공개 화면과 비공개 API를 분리하고 비공개 응답은 캐시 금지. 업로드 권한·첨부 접근도 게시물 권한과 함께 검사합니다.

## 구현 순서·완료 조건
